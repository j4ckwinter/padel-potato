### API and Source-Fidelity Boundary

- Model authored axes with closed discriminated TypeScript props; impossible or unsupported combinations must not be representable.
- Labels, displayed values, accessible names, and callbacks may be customized. Height, padding, radius, icon geometry, state colour, and content hierarchy remain component-owned.
- Preserve the canonical Penpot width in canonical stories. A Phase 2-style layout-only escape hatch may allow width/flex placement without changing token-owned internal geometry.
- Persistent state is controlled by the consumer. Stories may use local harness state; production components do not own product state.
- Pressed and focused are transient native interaction states derived from `Pressable`/`TextInput` events. They are story specimens, not production props.
- `disabled`, `loading`, `readOnly`, `selected`/`checked`, value, and validation disposition are persistent supported inputs where applicable.
- Unsupported runtime values throw the established actionable design-system diagnostic. Components never silently substitute an approximation.
- Normalize Penpot `Favourite` axis `Property 1` to public `checked`. Normalize the `Icon Button` `Value 2` record to the same `notification` exemplar because revision 296 contains identical Notification geometry in both records; public customization uses the existing closed `IconName` union. Retain both source mappings in the Phase 3 source registry.

## Spacing Scale

### Default presentation scale

| Scale step | Token | Usage |
|------------|-------|-------|
| 4 | `space4` | Tight status/detail separation |
| 8 | `space8` | Icon-label gaps and compact internal separation |
| 16 | `space16` | Standard horizontal control padding and component grouping |
| 24 | `space24` | Section grouping and authored pill radius relationship |
| 32 | `space32` | Catalogue section separation |
| 48 | Not authored | Do not synthesize a spacing token |
| 64 | Not authored | Do not synthesize a spacing token |

Component dimensions are geometry, not new spacing tokens:

- Button: 160 canonical width; 40 or 48 height; 16 horizontal padding; 8 content gap.
- Icon Button: 40 or 44 square; a 40 visual uses the Phase 2 two-point hit expansion.
- Favourite: 44 square. Checkbox: 40 square with a minimum effective 44 target.
- Choice Chip: 148×40 canonical specimen with fixed authored 12-point horizontal inset. Day selector: 104×72. Time selector: 112×56.
- Field: 350×84 normally and 350×100 when helper/error content is present.
- Social Sign-In Button: 352×48. Auth Divider: 352×24.
- Segmented Control: 350×48. Bottom Navigation: 390×76.
- App Header: 390×112. Section Header: 350×28 visual row inside a 354×44 interaction-clearance wrapper.

Canonical widths belong to source-faithful stories. Responsive placement may change outer width through the approved layout-only seam, but internal height, padding, radii, target sizes, and content order remain fixed to the source.

The Choice Chip's 12-point inset and any other revision-296 measurement outside the reusable scale are fixed component geometry, not spacing tokens or caller-selectable scale values. They must be retained in source evidence and component tests without expanding the public spacing scale.

Exceptions:

- All interactive controls expose an effective target of at least 44×44. Visual 40 controls use non-visual expansion without changing their authored appearance.
- Parent layouts must leave enough room for hit expansion; clipping the expanded target violates the contract.
- Fractional Penpot widths such as `352.00000000000006` and `389.9999999999998` normalize to their exact authored integer dimensions 352 and 390 and must be recorded as harmless serialization normalization, not a visual deviation.

## Typography

### Default catalogue hierarchy

The Phase 3 catalogue uses exactly four default sizes and two default weights:

| Role | Token | Size | Weight | Absolute line height |
|------|-------|------|--------|----------------------|
| Supporting | `caption` | 11 | 400 | 13.2 |
| Body | `body` | 14 | 400 | 16.8 |
| Heading | `heading` | 18 | 700 | 21.6 |
| Display | `display` | 28 | 700 | 33.6 |

The reusable Phase 3 typography contract is exactly the four rows above: sizes 11, 14, 18, and 28 with weights 400 and 700. No additional size or weight becomes a reusable Phase 3 role.

Revision 296 contains fixed authored text treatments in compact controls such as Button, Bottom Navigation, Choice Chip, Segmented Control, Social Sign-In Button, selector labels, and the Section Header action. Preserve those values verbatim in the family source registry and render them as component-owned geometry. They are not named or exported as additional typography-scale roles, are not caller-selectable, and must not be rounded or silently remapped to the reusable hierarchy. Canonical source-record tests compare the fixed font family, size, weight, line height, and letter spacing directly with retained Penpot evidence.

Contract:

- Reusable roles use the matching `Inter_400Regular` or `Inter_700Bold` family. Fixed source-specific component text uses its retained local Inter asset and exact evidence record; do not request native weight synthesis.
- `allowFontScaling` remains enabled; do not impose a default `maxFontSizeMultiplier`.
- Text-bearing controls preserve the accessible name at large text. Labels wrap where the component can grow; fixed compact navigation labels use one-line truncation only in a dedicated boundary disposition, never silent clipping.
- Canonical stories retain Penpot copy and metrics. Boundary stories use intentionally long labels and 200% font scaling without altering the canonical specimen.

## Interaction and State Contract

### Shared rules

- All action components compose the Phase 2 `Pressable` and reuse one blocked predicate. Disabled or loading means native disabled state, semantic state, callback suppression, and stable visual disposition agree.
- A completed enabled press emits exactly one callback. Disabled/loading controls emit none.
- Native focus/blur drives focus indication. Native pressed render state drives pressed styling. Neither is a persistent public prop.
- Controlled components emit the requested next value/destination; they do not update themselves unless a Storybook harness supplies state.
- Select/date/time Field variants are trigger controls only. They do not open overlays, calendars, clocks, or product pickers.
- Navigation components emit callbacks only. They do not import a router or mutate application navigation state.

### Component-specific behavior

| Component | Required controlled behavior |
|-----------|------------------------------|
| `Button` | `onPress`; optional `disabled`/`loading`. Loading preserves its accessible name, sets busy+disabled, and blocks activation. |
| `IconButton` | Required `accessibilityLabel`, closed `IconName`, `onPress`, `disabled`. |
| `Favourite` | `checked`, `onCheckedChange(next)`, optional disabled. Visible heart and checked semantics update from the controlled prop. |
| Text/password/search `Field` | Native `TextInput`; `value` + `onChangeText`. Password uses secure entry and a labelled visibility action. Search may expose a labelled clear action. |
| Select/date/time `Field` | Displayed value + `onPress`; role button; no picker ownership. Empty value shows placeholder. |
| Stepper `Field` | Controlled numeric/display value plus decrement/increment callbacks; both child actions are separately named, separately disabled at bounds, and each has an effective 44 target. |
| `ChoiceChip` | `selected` + `onSelectedChange(next)`; option behaves as a radio choice, filter as a checkable filter. |
| `Checkbox` | `checked` + `onCheckedChange(next)`; no indeterminate state because Penpot does not define one. |
| `DayTimeSelector` | `selected` + `onSelect`; behaves as a radio choice within its caller-owned group. |
| `SocialSignInButton` | `onPress` and optional disabled; no authentication SDK, network request, spinner, or backend state. |
| `BottomNavigation` | Controlled `activeDestination`; each destination emits `onDestinationPress(destination)`, including Create. Fixed order and labels/icons remain source-owned. |
| `SegmentedControl` | Controlled selected value, 2–4 typed options, `onValueChange`; disabled blocks every segment. |
| `AppHeader` | Configuration-specific callbacks only: back, notification, overflow, or favourite as supported by the selected page. Unsupported action slots are absent from the discriminated props and accessibility tree. |
| `SectionHeader` | If action copy is visible, `onActionPress` is required; when absent, no empty press target renders. |

## Accessibility Contract

| Family | Native semantics |
|--------|------------------|
| Button, Icon Button, social sign-in, header actions, Section Header action | `accessibilityRole="button"`; stable accessible name; disabled/busy as applicable. |
| Favourite | Toggle semantics with checked state and a stable name such as `Add Alex to favourites`; selected state changes the announced checked value, not the name. |
| Checkbox | `accessibilityRole="checkbox"`; `accessibilityState.checked`; disabled as applicable. |
| Choice Chip option | `accessibilityRole="radio"`; checked state; caller/group supplies a meaningful group label. |
| Choice Chip filter | `accessibilityRole="checkbox"`; checked state communicates active filtering. |
| Day Time Selector | `accessibilityRole="radio"`; accessible name combines the visible day/date or time/availability content; checked state marks selection. |
| Text/password/search Field | Native editable text semantics. Accessible name comes from visible label; hint/validation/required information remains available without replacing visible copy. |
| Select/date/time Field | Named button with `accessibilityValue.text` equal to the selected value or placeholder. |
| Stepper Field | The displayed value is exposed; decrement/increment are individually named buttons and announce disabled bounds. |
| Bottom Navigation | Each destination is an individually named tab with `accessibilityState.selected`; no single opaque group control. |
| Segmented Control | Each segment is an individually named tab with selected state; focus order follows visual order. |
| App Header | Title is a header; subtitle follows it; only visible actions enter the focus order. Mascot and nested action icons are decorative. |
| Section Header | Title is a header; the optional action is a separately named button. |
| Auth Divider | `or` remains readable static text; decorative lines are hidden. |

Further requirements:

- Visible label, hint, required marker, success, and error copy remain present. Do not encode error state only through border colour.
- Every compact visual control preserves the minimum 44×44 effective target. Nested icons do not become duplicate accessibility elements.
- Reading and focus order follows visible left-to-right/top-to-bottom order. Bottom Navigation and Segmented Control do not collapse multiple destinations into one control.
- At 200% font scaling, required actions remain reachable and semantic text remains complete. Native visual proof, VoiceOver, and TalkBack acceptance remain Phase 5, but the host contract and boundary stories are required now.
